# Info Cooperazione — data source reference

Recorded during `/add-portal` Step 2 (2026-09-24) from a handful of requests
with the CLI's own User-Agent. No account, no cookies, no impersonation.

## Architecture

`https://www.info-cooperazione.it` is a server-rendered ASP.NET Core site
(Bootstrap theme, antiforgery tokens on the cookie banner form). Listing and
posting pages are complete HTML: there is no JSON API behind them, no RSS or
Atom feed (`/rss`, `/feed` return 404) and no `sitemap.xml` (404). The job
section is category 3 ("Lavoro") of the site's generic category search.

## Search (listing)

```
GET https://www.info-cooperazione.it/Category/Search?Cat=3&s=<text>&paese_id=<id>&lavoro_non_scaduti=True&page=<n>
```

This is the site's own search form (`<form id="searchform" action="/Category/Search">`
on `/Category/lavoro`), submitted with GET.

| CLI flag | Site parameter | Notes |
|---|---|---|
| — | `Cat=3` | The jobs category. Fixed. |
| `-q` | `s` | Free text. See *Query semantics*. Omitted when empty. |
| `-l` | `paese_id` | One numeric country id. Names are resolved through the form's `<select name="paese_id">` (see *Countries*). |
| — | `lavoro_non_scaduti=True` | "Solo aperti": postings whose deadline has not passed. The form's default (checked). Fixed. |
| `--page` | `page` | 1-indexed, same as the CLI. A page past the end returns 200 with no cards. |
| `--jobage` | — | No site parameter. Filtered client-side at month precision (see *Dates*). |
| — | `organizzazione_id` | Organisation filter (363 organisations in the form's select). Not exposed by the CLI. |
| — | `ordina_per` | Empty (default) = by publication date, newest first; `data_scadenza_desc` = by deadline. The CLI keeps the default. |

`URLSearchParams` encodes a space as `+`, which the server reads as a space
(verified: `program manager` returned the 3 expected postings).

**Page size** is 20 cards (not 25). At recon there were 63 open postings:
pages 1–3 full, page 4 with 3 cards.

### Query semantics (verified live)

- **Case-insensitive substring over title and body, as one phrase.**
  `logistic` matched "Logisticien" and a posting whose body mentions
  logistics; `program manager` → 3 postings; `manager program` → 0.
- **Under 3 characters → no results.** `IT` → 0 and `HR` → 0, while
  `hr manager` → 1 ("Field HR Manager"). The CLI refuses 1–2 character
  queries with `BAD_ARG` rather than return a silent empty list.
- **Boilerplate matches.** `dati` → 9 postings, most through the privacy line
  "trattamento dei dati". `informatica` → 1, `digitale` → 1, `ICT` → 0 at recon.

### Pagination

```html
<nav aria-label="pagination-wrapper" class="pagination-wrapper">
  <ul class="pagination justify-content-center">
    <li class="page-item active"><span class="page-link">1</span></li>
    <li class="page-item"><a class="page-link" href="?Cat=3&amp;...&page=2">2</a></li>
    ...
    <li class="page-item"><a class="page-link" href="?...&page=2" aria-label="Next">...</a></li>
```

`meta.hasNext` = a `class="page-link"` anchor with `aria-label="Next"` exists.
There is no total-count element on the page.

### Card anchors

The listing sits in `<div class="block category-listing category-style2">`.
`parseJobCards` cuts the page at `<nav ... pagination-wrapper` (so the sidebar,
which reuses the same card classes for news teasers, is never read) and
splits on:

```html
<div class="post-block-wrapper post-list-view clearfix">
```

Per card:

| Field | Anchor | Example |
|---|---|---|
| `id`, `url` | `<h2 class="post-title title-large"><a href="/2026/9/<slug>">` | `/2026/9/intersos-finance-intern-afghanistan-italia` |
| `headline` | text of that anchor, always `ORG - Role - Place` | `INTERSOS - Finance Intern - Afghanistan / Italia` |
| `title` | `headline` minus the `ORG - ` prefix and the last ` - Place` segment | `Finance Intern` |
| `roleCategory` | `<small><strong>Posizione: X</strong></small>` | a **standardised tag**, not the title: "RTM - Program Manager - Kosovo" is tagged `Project Manager`; two admin-assistant roles are tagged `Admin` |
| `company` | `<a href="/Category/Search?Cat=3&organizzazione_id=N"><small> X </small></a>` | `INTERSOS` (short name) |
| `location` | `<a href="/Category/Search?Cat=3&paese_id=N"> X </a>` | `Afghanistan`, `Più paesi` (id 188) |
| `deadline` | `<small class="text-danger"><strong>Scadenza: 07 ottobre 2026</strong></small>` | Italian long date |
| `summary` | `<div class="righe-4">` | plain text, cut by the site at ~400 chars |
| `contractType`, `duration`, fallback `deadline` | the summary's first sentence, generated by the site | `... Durata 6 mesi. Tipo contratto: Stage/Tirocinio Scadenza candidature 07/10/2026` |

When a posting has no duration the site still writes `Durata  mesi.`; the
CLI turns a duration without a digit into `null`. `Tipo contratto` values
seen: `Tempo det.`, `Tempo indeterminato.`, `Co.co.co.`, `Consulenza`,
`Stage/Tirocinio` (kept verbatim, trailing dot included).

## Dates

- **No publication day on listing cards.** Every date on the listing page is
  a deadline. The URL path carries the publication year and month
  (`/2026/9/...`), emitted as `publishedMonth`; search `date` is `null`.
- `--jobage N` keeps a card when `publishedMonth >= month(now - N days)`
  (UTC). This is a superset of the true window, never a subset.
- The posting page carries the exact day (below). Fetching every posting to
  fill `date` in search would cost 20 requests a page, so the CLI does not.

## Detail (posting page)

```
GET https://www.info-cooperazione.it/<year>/<month>/<slug>
```

The month is not zero-padded (`/2026/9/...`). A missing slug returns a real
HTTP 404 (`<title>404 - Errore - Info-Cooperazione.it`).

| Field | Anchor |
|---|---|
| `headline` | `<div class="post-body mt-0"><h2 ...>` text; fallback `<meta property="og:title">` |
| `company` | first `<b class="">` inside `<div class="post-header mt-2">` |
| `roleCategory` | `Posizione: X</strong>` inside the header |
| `location` | text after `<i class="fa fa-map-marker"></i>` up to `</small>` |
| `date` | `<a href="#" class="post-category bg-black">08/09/2026</a>` (dd/mm/yyyy) |
| `deadline` | `Scadenza: 30 settembre 2026` in the header |
| `description` | inner HTML of `<div class="entry-content text-justify">`, extracted with div balancing (bodies are pasted Word HTML and may nest divs) |
| `applyUrl` | the `<a href="...">` whose text is `LINK ALLA VACANCY` (absent when applications go by email) |

Body quirks handled by `htmlToText`: every bullet is often its own
`<ul><li>…</li></ul>` (adjacent lists are merged), spans carry
`data-ccp-props="{&quot;…&quot;}"` attributes (stripped with the tags), and
some bodies contain a double-encoded `&amp;n bsp;` (removed).

## Countries

`--location` names are resolved against the form's own list, fetched from
`GET /Category/Search?Cat=3` (one extra request; a numeric id skips it):

```html
<select class="field form-control" name="paese_id">
  <option value="" selected>Scegli una voce...</option>
  <option value="1">Afghanistan</option>
  <option value="189">Africa</option>
  ...
  <option value="85">Italia</option>
  ...
  <option value="188">Più paesi</option>
```

191 entries at recon, in Italian, including regions (`Africa` 189,
`America Latina` 190, `Asia` 191) and `Più paesi` 188 for multi-country
roles. Names are HTML-encoded (`Costa d&#x27;Avorio`). Matching is exact
after case, accent and apostrophe normalisation, plus `Italy` → `Italia` and
`paesi vari` / `multiple countries` → `Più paesi`.

## Access and licence

- **robots.txt**: `https://www.info-cooperazione.it/robots.txt` returns
  **404** (the site's HTML error page). No robots rules exist, so nothing is
  disallowed.
- **Terms of use**: none found. The footer links only *Privacy*
  (`/privacy-policy`), *Cookie Policy* and *Copyright* (`/pages/copia-pure`).
  No page mentions scraping, crawling or automated access.
- **Licence** (`/pages/copia-pure`, heading "COPIA PURE"): the site states
  that, unless otherwise specified, "i contenuti di Info Cooperazione sono
  rilasciati sotto Licenza Creative Commons Attribuzione 4.0". The sentence
  links to `https://creativecommons.org/licenses/by-nc-sa/4.0/deed.it`, and
  the page lists the conditions **Attribuzione**, **NonCommerciale** and
  **StessaLicenza**, so the effective licence is **CC BY-NC-SA 4.0** (the
  link text says only "Attribuzione 4.0"). For web reuse it asks for a live
  link to the page and the citation
  `www.info-cooperazione.it – La community italiana della Cooperazione Internazionale`.
  The CLI puts that citation in every record's `source`, plus
  `license`/`licenseUrl` in `meta.attribution` and in `detail`.
- **Login**: the header has a *Login* link (for members and publishers). Not
  needed for anything the CLI reads.
- The CLI identifies itself as `Mozilla/5.0 (compatible; infocooperazione-cli/1.0)`
  (accepted: 200 on every page tried) and backs off exponentially with jitter
  on 429/5xx (max 6 retries, 15 s per-attempt timeout). One request per
  search page, one more for a country name, one per detail.

## If it breaks

1. **Search returns 0 results for a query that has hits on the site**: open
   `/Category/lavoro`, check the form still uses `name="s"` and `Cat=3`.
2. **Cards come back empty or with null fields**: check the card wrapper class
   `post-block-wrapper post-list-view` and the anchors in the card table above.
   If the sidebar starts leaking in, check the `pagination-wrapper` cut.
3. **`-l <name>` fails with PARSE_ERROR**: the `<select name="paese_id">`
   moved; any page with the search form will do as the lookup source.
4. **`detail` PARSE_ERROR**: check `<div class="post-body` + `<h2>` and
   `og:title`. Empty `description`: check `<div class="entry-content`.
